# 26-w05-web-plan

5주차 실습② — **보안회사 원페이지 웹사이트 (Plan 기반 제작)**

방금 인라인으로 만든 것과 **동일한 요구사항**의 보안회사 웹사이트를, 이번엔 GitHub Copilot **Plan 모드**로 계획을 먼저 세운 뒤 **Start Implementation**으로 Agent에게 실행을 넘겨 완성하는 실습입니다.

## 시작하기

1. 이 저장소를 **Fork**
2. Fork한 저장소를 로컬에 **Clone**
3. [`guide.md`](./guide.md)를 따라 순서대로 진행

## 만들 결과물 (지난 실습과 동일)

```
nav (앵커링크: Hero / Services / About / Contact)
 └─ hero (회사 슬로건 + 버튼)
 └─ services (서비스 카드 3개, 각 카드에 "자세히 보기" 링크)
 └─ about (회사 소개)
 └─ contact/footer (연락처)
```

파일 구성: `index.html` / `style.css` / `script.js`

## 오늘 쓰는 방식

```
[Plan] 계획 세우기 (코드 변경 없음)
    ↓ "Start Implementation" 클릭
[Agent] 계획대로 파일 생성·수정 (실행)
```

## 배포

GitHub Pages로 배포합니다. 자세한 방법은 `guide.md`를 참고하세요.

## 💬 실습 소감: 인라인(Inline) vs 플랜(Plan) 모드 비교

> **"인라인은 흐름을 끊지 않고 즉각적으로 결과를 맞추는 직관성, 플랜은 복잡한 과정을 미리 내다보고 실수를 줄여주는 안전장치 같다."**

### 1. 인라인 vs Plan+Agent 비교 정리

| 비교 항목 | 인라인 (지난 실습) | Plan + Agent 기반 (이번 실습) |
|---|---|---|
| **체감 작업 속도** | 시작은 빠르나 세부 수정이 반복되며 후반 소요 시간 증가 | 초반 계획 검토 시간이 들지만, 구현 단계는 원클릭으로 일괄 처리되어 훨씬 빠름 |
| **재시도 / 되돌림 횟수** | 맥락이 끊기거나 의도와 다르게 나와 여러 번 롤백 및 재요청 발생 | 사전에 전체 구조와 순서를 점검하고 시작하여 되돌아가는 횟수가 대폭 감소함 |
| **다중 파일 제어** | HTML, CSS, JS를 오가며 개별적으로 프롬프트를 줘야 함 | 단 한 번의 요청으로 여러 파일 간의 연계(스타일, 마크업, 스크립트)가 일관되게 반영됨 |
| **요구사항 누락 여부** | 섹션이나 세부 동작(반응형 메뉴 등)이 누락되기 쉬움 | 계획서에 5개 섹션과 기능이 체크리스트 형태로 명시되어 누락 없이 완성됨 |
| **전체적인 완성도** | 부분 부분 패치하는 느낌이 강함 | 전체 아키텍처가 조화롭고 완성도 높은 결과물 도출 |

### 2. 종합 소감 및 배운 점

- **인라인 모드의 직관성과 즉시성**:
  작은 단위의 코드 작성이나 즉각적인 피드백이 필요할 때는 파일 내에서 흐름을 깨지 않고 코딩할 수 있어 매우 직관적이고 편리했습니다. 하지만 프로젝트 규모가 커지고 여러 파일에 걸친 변경이 필요할 때는 전체 맥락을 유지하기 어렵다는 한계가 있었습니다.
- **Plan + Agent 모드의 안정성과 확장성**:
  코드를 작성하기 전 '계획 수립' 단계를 거치면서 전체 구조를 조망할 수 있었고, 무엇보다 `Start Implementation`을 통해 여러 파일(`index.html`, `style.css`, `script.js`)을 동시에 유기적으로 생성·수정하는 과정이 매우 효율적이었습니다. 복잡한 요구사항일수록 실수를 방지하고 결과물의 일관성을 보장해주는 훌륭한 안전장치 역할을 해주었습니다.
- **결론**:
  단순한 함수나 단일 파일의 빠른 수정에는 **인라인 방식**, 전체 웹페이지 제작이나 아키텍처 단위의 다중 파일 개발에는 **Plan + Agent 방식**을 적재적소에 활용하는 것이 최적의 AI 페어 프로그래밍 워크플로우임을 체감할 수 있었습니다.
